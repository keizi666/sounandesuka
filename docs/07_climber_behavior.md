# 07 登山者モデル（移動・ナビゲーション・行動）

## 1. 移動（`movement.ts`）

### 1.1 登山道上の候補速度

```
s      = 実効勾配 = dh / (水平距離 * sinuosity)       （10 m 区間ごと、進行方向）
vTobler[km/h] = 6 * exp(-3.5 * |s + 0.05|)
v = vTobler
  * pace                      pace = 0.75 + 0.15*experience + 0.1*(fitness-1)   （既定で約 0.8）
  * classF                    T1 1.0 / T2 0.85 / T3 0.6 / 鎖場 0.45
  * darkF                     暗くない 1.0 / ヘッドランプ 0.75 / ライトなし 0.25 + 0.2*moonIllum
  * visF                      vis < 30m: 0.8、それ以外 1.0
  * snowF                     積雪 5cm 超: 0.75、20cm 超: 0.5、凍結(icy)かつアイゼンなし: 0.6
  * wetF                      地面 wet>0.5 かつ T2/T3: 0.9
  * (1 - 0.4*(fatigue/100)^2)
  * M_motor
  * injuryDownF               捻挫で下り 0.8
  * hurryF                    急ぐ指示/不安>60: 1.1
  * paceAdj(edge)             エッジのコースタイム合わせ係数（既定 1.0。docs/16 §4.4）
  * windF                     強風: clamp(1 - max(0, wind - 8) / 14, 0.25, 1)（10〜15 m/s で意志どおりに歩けなくなり、
                              15 m/s を超えるとほぼ歩けない、という報告に合わせる。耐風姿勢で止まる時間を含む平均）
```

**風による運動負荷**: 歩行中の MET に `1 + 0.03 × max(0, wind − 5)` を掛ける（15 m/s で 1.3 倍、22 m/s で 1.5 倍）。
**突風による転倒**: 局地風 × 突風係数が 20 m/s を超える 10 m ごとに、転倒判定の `p10` を ×(1 + (gust − 20) / 5) する（docs/08 §1.2）。

その後 `docs/06` §2.2 の MET 上限で制限。パーティは最も遅い人に合わせる（`party.cohesion`）。

### 1.2 道外の候補速度

`v = 3.0 km/h * vegSpeed[veg] * slopeF * darkF * M_motor * (1 - 0.4*(F/100)^2)`、`slopeF = max(0.15, cos(slope)^2)`。

### 1.3 コースタイムの検証

標準登山者（experience 0.5, fitness 1.0, 荷物 8 kg、晴天、昼）が各エッジを歩いた時間が、マップの `courseTimeMin` の ±25% に入ること（`tests/movement.test.ts`）。外れたら `sinuosity` を調整する。

### 1.4 大人数パーティと分割

- パーティは最大 20 人。`groups`（docs/09 §3.1）に分かれ、行動・分岐点はグループ単位。
- `cohesion: "tight"`（既定）: グループは最も遅い人に合わせて進み、遅れた人を待つ。
- `cohesion: "loose"`: 先頭（グループのリーダー）は自分の速度で進み、他の人はそれぞれの速度で後を追う。列が伸び、行動不能になった人はその場に残る。リーダーは 30 分ごとに人数確認の判定（`p = 0.5 × J`）を行い、成功すれば遅れを認識する（汎用分岐点 `straggler`）。
- 行動不能（M = 0）になった人が出ると、`tight` のグループは全員停止して `STAYING`（吹きさらしで立って待つ）になる。これが分岐点の発火条件として使える。

## 2. 行動の状態機械（`behavior.ts`）

```
                ┌──────────── WALKING ◄──────────┐
   start ──► WALKING ⇄ RESTING                     │
                │ 迷い（気づかず）                  │ 道に戻る
                ▼                                  │
          OFFROUTE_UNAWARE ──気づく──► LOST_AWARE ─┼─► BACKTRACKING
                                         │          ├─► NAVIGATING_TO_TRAIL (GPS)
                                         │          ├─► DESCENDING_DRAINAGE (沢下り)
                                         │          ├─► SEEKING_SIGNAL
                                         │          └─► STAYING
   どこからでも: BIVOUAC / SHELTERED / WAITING_RESCUE
   身体から: INCAPACITATED → UNCONSCIOUS → DEAD
   終端: FINISHED（下山口）/ RESCUED / DEAD
```

| 状態 | 毎ティックの処理 |
|---|---|
| `WALKING` | 計画ルートに沿って前進。ノード到着で次エッジ選択（§3.2 で誤りうる） |
| `RESTING` | `restUntil` まで停止。MET 1.4 |
| `SHELTERED` | 小屋内。`until` 条件（翌朝・天候回復）まで。営業小屋は「安全」扱い |
| `BIVOUAC` | 避難地点探索→移動→停止。`bivouacUntil` まで |
| `OFFROUTE_UNAWARE` | 偽の道を辿る、または道外を「計画方向」に進む（§3.4）。毎分気づき判定 |
| `LOST_AWARE` | その場で停止し、分岐点（汎用 `lostAware` またはシナリオ定義）を待つ |
| `BACKTRACKING` | 自分の軌跡を逆に辿る（§3.5） |
| `NAVIGATING_TO_TRAIL` | A* で最寄りの登山道点へ道外移動 |
| `DESCENDING_DRAINAGE` | 下り＋沢筋に引かれる道外移動（§3.6） |
| `SEEKING_SIGNAL` | 半径 600 m 内で電波が最大の到達可能セルへ登る。到達したら救助要請を自動試行 |
| `STAYING` | その場で待機（風下探索なし）。体温低下で汎用分岐点が出る |
| `WAITING_RESCUE` | 救助要請済みで待機。ビバークと同じ熱環境（ツェルトがあれば使う） |
| `INCAPACITATED` | M == 0。動けない。熱環境は STAYING と同じ（ツェルト内ならそれを維持） |
| `UNCONSCIOUS` | `conscious == false` |

状態遷移は `behavior.transition(c, next, reason)` 経由で行い、`SimEvent { type: "STATE", ... }` を出す。

## 3. ナビゲーション（`navigation.ts`）

### 3.1 手がかりの見えにくさ `cue`（0〜1）

```
visCue  = clamp(1 - vis / 200, 0, 1)
darkCue = isDark ? (headlampOn ? 0.45 : 0.9) : twilight ? 0.2 : 0
snowCue = snowCm > 10 ? 0.5 : snowCm > 3 ? 0.2 : 0
cue = max(visCue, darkCue, snowCue)
navEff = navSkill * J
```

### 3.2 分岐での誤り

ノード到着時、計画上の次エッジ `intended` に対して、そのノードの `confusers` のうち `whenIntending` に `intended` を含むものを候補とする。

```
for each confuser k:
  p_k = ambiguity_k * (0.3 + 0.7*cue) * (1 - 0.85*navEff) * (1.5 - markers(intended)*0.5)
  if c.stopCheckedAt(node): p_k *= 0.1      // 「立ち止まって地図を確認」アクション済み
  if c.hasGpsCheckHabit && phoneOk: p_k *= 0.4
p_err = min(0.95, 1 - Π(1 - p_k))
```

`nav` ストリームで誤り判定し、誤った場合は `p_k` に比例して誤りエッジを選ぶ。誤りエッジに入ると:
- `kind: "false"` → `OFFROUTE_UNAWARE`（偽の道を辿る）
- 正規のエッジ（別ルート）→ 状態は `WALKING` のまま `routeBelief`（本人は正しいと思っている）と真のルートがずれる。次ノード到着で `awareness` 判定（ノード名の道標を見る: `p = 0.6 + 0.4*markers` × (1-visCue*0.5)）。気づけば `LOST_AWARE`。

### 3.3 道の途中での踏み外し

10 m 進むごとに `p = drift(edge)/10 * cue * (1 - 0.8*navEff) * (1 + fatigue/100)`。
起きたら、その地点から `OFFROUTE_UNAWARE`（道外）へ。進行方向は直前の道の方向を保つ。

### 3.4 気づかない間の移動

- 偽の道上: 道のポリラインを辿る。`fadeOutM` 区間で `drift` が線形に 1.0 まで上がり、末端で道外へ。
- 道外: 毎ステップ（1 セル = `map.cell` m 単位）、8 近傍から効用最大のセルを選ぶ:

```
U(cell) = 1.0 * cos(angle(cell - pos, beliefDir))      // 本人が向かっているつもりの方向
        + 0.8 * max(0, -dh/cell) * descendBias         // 下りやすさ（descendBias = 0.6 既定）
        - 1.2 * slopePenalty(slope)                    // 35°超で急増
        - 0.8 * (1 - vegSpeed[veg])                    // 藪を避ける
        - cliffPenalty(cell)                           // 崖が「見えている」場合のみ 10
        + noise(nav) * 0.3
崖が見えている = (vis > 40 && !(isDark && !headlampOn))  かつ 距離 ≤ 視程
```

視程が悪い・暗いときは崖に隣接するまで気づかず、崖セルに入ると転落判定（`docs/08` §1）。

### 3.5 気づき（`OFFROUTE_UNAWARE` → `LOST_AWARE`）

毎分:

```
p = 0.01 + 0.04*navEff
  + (道外で藪こぎ中 ? 0.06 : 0)
  + (偽の道が消えた直後 ? 0.15 : 0)
  + (GPS 確認習慣の予定時刻 && phoneOk && gpsApp ? 1.0 : 0)
p *= (anxiety > 60 ? 1.2 : 1)
```

気づいた瞬間に `lastKnownOnRoute`（最後に正規ルート上にいた点）を記録済みであること（逸脱時に保存しておく）。

### 3.6 戻る・GPS・沢下り

**BACKTRACKING**: 自分の軌跡（逸脱以降を 10 m ごとに `c.track` に保存）を逆順に辿る。
GPS アプリで軌跡記録中なら確実。そうでなければ 100 m ごとに `p_lose = (1-navEff)*0.12*(0.3+cue)` で軌跡を見失い、
見失うと `OFFROUTE_UNAWARE`（`beliefDir` = 軌跡の逆方向）に戻る。`lastKnownOnRoute` に着けば `WALKING` に復帰しルートを再計算。

**NAVIGATING_TO_TRAIL**: `checkPosition` 成功後に選べる。A*（コスト = 1/道外速度、崖は不可、地形グリッド上）で最寄りの正規登山道サンプル点へ。

**DESCENDING_DRAINAGE**（「下れば道か林道に出るはず」）: §3.4 の効用で `beliefDir` を使わず
`U = 1.2*max(0,-dh/cell) + 0.6*flowAccGradient + ...` とし、沢筋へ吸い込まれていく。沢セルでは速度 0.35、
knickpoint（滝）に達すると崖として扱う。視程が良く判断力があれば（`J > 0.5 && 見えている`）滝の手前で止まり、汎用分岐点 `waterfall` を発火。

### 3.7 位置確認（`checkPosition`）

- GPS アプリ＋電池 > 0: 3 分で成功。`awareLost` なら位置判明（`knowsPosition = true`）。電池 −2%。
- 紙地図＋コンパス: 視程 > 300 m かつ明るいとき `p = 0.3 + 0.6*navSkill` で成功（10 分）。それ以外は 0.1。
- 何もない: 失敗。

## 4. 自律ミクロ行動（`behavior.autonomous`）

毎ゲーム分 1 回評価。各行動は `behavior` ストリームで確率判定。所要時間中は `RESTING`。

| 行動 | 条件 | 1 分あたりの実行確率 | 所要 |
|---|---|---|---|
| 雨具を着る | `precip ≥ 1` かつ 未着用 かつ 雨具あり | `0.25 * (1 - delaysRainwear) * J`。`wetness > 0.5` または ノード到着時は `0.6*J` | 4 分（寒冷ストレスで ×1.5、手袋なし低温で ×2） |
| 防寒着を足す | `cloPack > 0` かつ（`core < 36.4` または 体感 < 0 で休憩中） | `0.3 * J` | 3 分 |
| 食べる | 食料あり かつ（習慣の間隔到来 または glycogen < 450） | 習慣 0.8 / 低下時 `0.5*J`（J<0.3 なら「食べることを思いつかない」で 0.05） | 3 分 |
| 飲む | 水あり かつ deficit > 0.5 | `0.3*J` | 1 分 |
| 休憩 | fatigue > 75 | 0.5 | 10 分 |
| ヘッドランプ点灯 | 暗い かつ あり かつ 電池あり | `0.7`（ザックの奥: `headlamp.inPack` なら 3 分） | |
| 雨具を脱ぐ | 降水なし 30 分 かつ 登りで core > 37.3 | `0.1*J` | 3 分 |

性格パラメータ `habits.delaysRainwear`（0〜1）が「もう少しで小屋だから」と着用を先延ばしにする傾向を作る。

## 5. 認知（`perception.ts`）

登山者ごとに主観的な状態を持つ。UI の「登山者の視点」と思考テンプレートが使う。

| 変数 | 内容 |
|---|---|
| `routeBelief` | 本人が今いると思っているエッジと位置 s |
| `awareLost` | 道迷いを自覚しているか |
| `knowsPosition` | 現在地を把握しているか（GPS/地図で確認後 true、移動 300 m で false に戻る） |
| `weatherImpression` | `fine / worsening / bad / severe`（局地気象から閾値で） |
| `timeBehindMin` | 計画との遅れ（本人の認識） |
| `feelsCold` | `core < 36.3` または 体感 < −5 |

## 6. 思考の吹き出し（`thoughts.ts`）

- 乱数は `thoughts` ストリームのみ（結果に影響させない）。
- 15〜30 ゲーム分ごとに 1 回、条件に合うテンプレートから優先度最大のグループを選び、その中からランダムに 1 つ。
- シナリオの `thoughts` は組み込みより優先度 +10。
- 同じテンプレートは 120 ゲーム分以内に再使用しない。

組み込みテンプレート（`src/i18n/ja.ts` の `THOUGHTS` に置く。抜粋）:

## 7. セリフ（`speech.ts`）

登山者が **声に出して言う言葉**。思考（§6、本人の内心）とは別物で、画面では角丸・尻尾付きの吹き出しで表示する（docs/11 §8）。

### 7.1 出どころ

| 出どころ | 例 | 優先度 |
|---|---|---|
| シナリオの `say` 効果・アクション（docs/09） | 分岐点で「引き返す」を選ぶと、リーダーが「ここで引き返そう」 | 30 |
| シナリオの `speech` テンプレート | 条件つきの台詞（§7.2） | 20 |
| 組み込みテンプレート（`i18n/ja.ts` の `SPEECH`） | 突風でリーダーが「しゃがんで！」 | 10 |

乱数は `thoughts` ストリームを使い、シミュレーション結果に影響させない（セリフを足しても決定論ハッシュは変わらない）。
セリフは行動を起こさない。行動はアクションが起こし、セリフはそれに添えて表示されるだけ。

### 7.2 テンプレートの評価

- 1 ゲーム分ごとに、話せる状態（`conscious` かつ §7.4 で発話可能）の登山者について条件に合うテンプレートを集め、優先度の高い順に 1 つ選ぶ。
- 同じ登山者のセリフは 3 ゲーム分以上あける。同じテンプレートは `cooldownMin`（既定 60）以内に再使用しない。
- パーティ全体で同時に話すのは最大 3 人（優先度順）。
- `to` を持つセリフ（話しかけ）には、相手が `reply` テンプレートで応じることがある（3〜20 ゲーム秒後）。

### 7.3 組み込みテンプレート（抜粋）

| key | 話し手 | 条件 | 例 |
|---|---|---|---|
| `gust_crouch` | グループのリーダー | 局地の突風が 20 m/s 超 | 「しゃがんで！」「風が来るよ、低く！」 |
| `rain_start` | 誰か | `RAIN_START` | 「降ってきたね」 |
| `ask_ok` | J の高い人 → 不安・体温が悪い人へ | 相手の coreC < 35.5 または anxiety > 60 | 「大丈夫？」「少し休もうか」 |
| `reply_ok` | 話しかけられた人 | `ask_ok` への応答で coreC ≥ 35 | 「うん、まだ大丈夫」 |
| `reply_bad` | 話しかけられた人 | `ask_ok` への応答で coreC < 35 | 「……さむい」 |
| `headcount` | リーダー | `straggler` 判定時 | 「みんないる？ 返事して！」 |
| `call_help` | 誰か | 同行者が行動不能になった | 「誰か！ 動けない人がいる！」 |
| `phone_call` | 通報する人 | `RESCUE_CALLED` | 「山で動けない人がいます。場所は……」 |
| `whistle` | 笛を持つ人 | 救助接近・夜間の待機 | 「ピーッ、ピーッ」（`sound: true` で擬音表示） |
| `lost_doubt` | 同行者 | `OFFROUTE_UNAWARE` が 15 分以上 | 「この道で合ってる？」 |

### 7.4 体温・状態による発話の変化（生理学的な対応）

低体温症の進行で構音障害（ろれつが回らない）、意味の通らない発語、無反応へと変わることに合わせ、発話を変形する（docs/06 §0, §7）。

| 状態 | 発話 | 表示上の変形（`speech.ts` の `distort()`） |
|---|---|---|
| core ≥ 35.0 | 通常 | なし |
| 34.0 ≤ core < 35.0 | 構音障害 | 語の途中に「…」、小さい「っ」を挿入。文を短くする（最初の読点まで）。吹き出しを小刻みに揺らす（震え） |
| 32.0 ≤ core < 34.0 | 混乱した発語 | テンプレートを `confused` 群（「かえる……」「あつい」「いま、なんじ」）に置き換え。確率 0.5 で発話しない |
| core < 32.0、または意識なし | 発話しない | 話しかけられても応答なし（周囲の人の `call_help` が発火しやすくなる） |
| 疲労 > 90 または 呼吸が荒い（MET > 0.8 × 最大） | 息切れ | 文を短く、「はぁ、」を前置 |

変形は表示文字列だけに適用し、イベントログには原文と「（ろれつが回らない）」の注記を残す。

### 7.5 史実シナリオでの扱い（架空のセリフの明記）

`historical` を持つシナリオでは、セリフを **記録** と **架空** に分け、架空のものは必ずそれと分かるように表示する。

| 区分 | 条件 | 表示 |
|---|---|---|
| 記録 | `documented: true` かつ `source` あり | 本文の下に「記録」バッジ。文言が残っていない場合は内容を括弧書き（例「（しゃがむよう声をかけている）」） |
| 架空 | それ以外すべて（組み込みテンプレート、シナリオの `speech`・`say` で `documented` のないもの、`distort()` で変形した文） | 本文の先頭に **※**、本文の下に「架空」バッジ |

- 判定は `speech.ts` の `classify(line, scenario)` に一本化し、UI・ログ・振り返りのすべてが同じ結果を使う（表示側で個別に判断しない）。
- イベントログ: `13:42 ガイドB ※「少し休もうか」（架空のセリフ）`。記録は `13:42 ガイドC「（しゃがむよう声をかけている）」（記録）`。
- 読み上げ用の `aria-live` 領域でも「架空のセリフ、」を先頭に付ける。
- ブリーフィングの注記に「※印のセリフは架空です。記録に残る発言には『記録』と表示しています」を加える。
- 架空のセリフでも、実在の人物の人格・評価を貶める内容、死の直前の具体的な言葉は書かない（シナリオ検証の警告対象: `speech` の `lines` に「死」「遺言」などの語があれば警告）。
- 設定「史実シナリオで架空のセリフを出す」（既定 ON）。OFF にすると記録のセリフだけを表示する。

史実を持たない架空のシナリオ（箱庭岳など）は、全体が架空であるためセリフに※は付けない。

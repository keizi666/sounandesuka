## P0 土台
- Vite + TS strict の雛形、`npm` スクリプト一式（中身が未実装のものはプレースホルダで exit 0）。
- `src/sim/types.ts`（appendix をコピー）、`src/sim/tuning.ts`（空の定数オブジェクト）。
- `tools/purity.ts`: `src/sim/**` に `Math.random`, `Date.now`, `performance.now`, `from 'three'`, `document`, `window` があれば失敗。
- `docs/PROGRESS.md` と `docs/DECISIONS.md` を作成。

**受け入れ**: `npm run typecheck && npm run test && npm run check:sim-purity` が通る。`npm run dev` で空の画面が出る。

## P1 乱数・時刻・地形
- `rng.ts`（xoshiro128**、名前付きストリーム、状態は 4 つの uint32 配列）
- `clock.ts`（TimeRef パース、表示、日の出入りから太陽高度）
- `noise.ts`, `generate.ts`, `derive.ts`（電波圏以外）, `sample.ts`
- `coverage.ts`（sim 内の純関数。Worker 化は P8）

**受け入れ**:
- rng: 同一シードで 1 万回の出力が一致、既知ベクトル（テストに固定値を記載）と一致。
- 地形: docs/04 §3.3 の 3 項目。生成が Node で 1 秒以内。
- 電波: docs/04 §7 の検証項目。
- `tools/sim.ts --dump-terrain` で高さマップを PGM 画像に出力でき、目視で尾根・谷・滝が確認できる（画像をコミットはしない）。

## P2 登山道と移動
- `trails.ts`（ポリライン化、ルート解決、ダイクストラ）
- `movement.ts`（Tobler、各係数）、`ClimberPos` と `posToWorld`
- 最小 World と `stepWorld`（移動のみ）

**受け入れ**: docs/07 §1.3 のコースタイム検証が全エッジで合格。s01 の計画ルートを標準登山者が歩くと休憩込みで 7.5〜10 時間（休憩は 50 分歩いて 10 分の固定パターンで計測）。

## P3 気象
- `global.ts`, `local.ts`, `ground.ts`, `sun.ts`

**受け入れ**:
- キーフレーム補間（風向の最短弧を含む）のユニットテスト。
- 同時刻で SUMMIT の気温が TH_SAWA より `lapse × 標高差` だけ低い（±0.5℃、ノイズ除外時）。
- SUMMIT の風速が J_FOREST（森林）の 2 倍以上（同時刻）。
- s01 で 15:00 以降に 2,200 m 以上が `sleet` または `snow`、`ground.snowCm` が D1 03:00 に 2,300 m で 1cm 以上。

## P4 生理
- `physiology.ts`, `capacity.ts`

**受け入れ**: docs/06 §9 の較正 C1〜C9 がすべて合格（`tests/physiology.calibration.test.ts`）。最終定数を `DECISIONS.md` に記録。

## P5 シナリオ・分岐点・結末
- `load.ts`, `validate.ts`, `conditions.ts`, `vars.ts`, `text.ts`, `choices.ts`, `events.ts`, `endings.ts`, `actions.ts`（道迷い系以外）, `behavior.ts`（WALKING/RESTING/SHELTERED/BIVOUAC/STAYING/INCAPACITATED）, 自律ミクロ行動, `policy.ts`
- `tools/sim.ts`, `tools/validate.ts`, `tools/simcheck.ts`

**受け入れ**:
- `npm run validate` で 3 シナリオ・1 マップがエラーなし。わざと壊した JSON（tests/fixtures）で期待どおりのエラーパスが出る。
- `npm run sim -- s01_cold_front --policy recommended --log` が結末まで走り、ログが時系列で読める。
- `npm run sim:check` 合格。

## P6 道迷い・危険・機器・救助
- `navigation.ts`, 残りの状態, `perception.ts`, `slip.ts`, `lightning.ts`, `devices.ts`, `rescue.ts`, `generic.ts`, `thoughts.ts`

**受け入れ**:
- s02 を `--policy bias` で 200 回: 道迷い発生率 40% 以上。`--policy recommended` で 200 回: 道迷い 15% 以下。
- 道迷い中に `descendDrainage` を強制した 100 回のうち、60% 以上が鬼ヶ沢に入り、20% 以上が魚止ノ滝に到達。
- s03 で山頂に `thunderLocal > 0.6` の間 30 分滞在させた 500 回の被雷率が 5〜25%。森林内に同時間いた場合は 2% 以下。
- 電波のない地点での `callRescue` が失敗し、`seekSignal` で電波圏に移動後に成功する。
- 夜間にヘリが飛ばないこと（ユニットテスト）。

## P7 記録・モンテカルロ・調整
- `recorder.ts`, `lessons.ts`, `snapshot.ts`, `tools/mc.ts`

**受け入れ**:
- 決定論テスト（docs/14 §2）合格。
- 3 シナリオすべてが `balanceTargets` を満たす（`npm run mc` で合否表示）。満たさない場合はシナリオ JSON の数値（天候・装備）か `tuning.ts` を調整し、調整内容を `DECISIONS.md` に記録。
- 1 回の通し実行（24 時間分）が Node で 50ms 以下。

## P8 ジオラマ描画
- `view/renderer.ts`, `diorama.ts`（台座・側面）, `terrainMesh.ts`, `terrainMaterial.ts`（色・質感・夜）, `vegetation.ts`（docs/10 §5.2）, `trails.ts`, `structures.ts`（§5.3）, `climberFigure.ts`（ブロック玩具風の人形、§5.1）, LOD の切替, `camera.ts`（俯瞰・追従）, `app/loop.ts`
- `coverage.worker.ts`

**受け入れ**: s01 を開始すると箱庭が表示され、登山者が補間で滑らかに歩き、時刻で光が変わる。人形が状態に応じて歩く・座る・しゃがむ・倒れるの姿勢を取り、雨具の着用で見た目が変わる。秋のシナリオで広葉樹が紅葉している。中品質で 60fps（開発機）、低品質で簡略モデルに切り替わる。

## P9 気象の描画
- 雲層、高度フォグ、降水、雷雲・稲妻、積雪・濡れ、空、オーバーレイ、登山者視点カメラ、注目ピン

**受け入れ**: s01 で稜線が雲に隠れ、雨がみぞれ・雪に変わる様子が見える。s03 で積乱雲が移動し稲妻が光る。夜はヘッドランプだけが光る。低品質でも破綻しない。

## P10 UI
- docs/11 の全画面・全コンポーネント（DebriefScreen を除く）、情報モード、判断時間制限モード、観察のみモード、キーボード
- セリフ（docs/07 §7、`speech.ts`）と吹き出し（docs/11 §8: 角丸・尻尾付き、思考との区別、追従、重なり回避、画面外、発話の変形）

**受け入れ**: 3 シナリオをブラウザで最初から結末まで遊べる。スマホ幅 360px で操作可能。
吹き出しは、カメラを回しても尻尾の先端が話し手の頭を指し続ける。3 人が同時に話しても重ならない。体温 34℃台の登山者のセリフが揺れて表示され、32℃未満では話さない。s04 で表示されるセリフのうち記録以外はすべて※と「架空」付きで表示される。セリフを有効・無効にしても決定論ハッシュが変わらない。

## P11 振り返り・What-if
- `DebriefScreen`, 2D 地図, グラフ, `whatif.worker.ts`, やり直し

**受け入れ**: s01 の振り返りで全分岐点の What-if が 20 秒以内（開発機）に揃う。やり直しで分岐点から再開できる。

## P12 保存・設定・仕上げ
- 自動保存・再開、履歴、設定、画質自動判定、エラー時の案内（WebGL2 非対応）、ビルドと `VITE_BASE`
- 高品質アセットの後読み込み（docs/10 §10）

**受け入れ**: リロードしても続きから再開できる。`npm run build` の成果物をサブディレクトリに置いて動作。初回ロード容量が NFR-03 以内（追加アセットを除く）。高品質で追加アセットが届くと差し替わり、読み込みに失敗しても基本のモデルで動き続ける。

## P13 可変マップとバンドル
- `MapRuntime` の `cell`/`half` 化、`terrain.type: "heightmap"` の復元、`smooth: false`、`paceAdj`、`vegetation.overrides`、`radio.paint`、`nodeOverrides`
- バンドルの読み込み（`index.json` の `bundle`、ファイル選択、ドラッグ＆ドロップ）、出典表示、実在の山の注記
- テスト用に、箱庭岳を 385 頂点で高さマップ化したバンドル `tests/fixtures/sounan385.sounan.json` を生成するスクリプト（`tools/make-fixture-bundle.ts`）

**受け入れ**: 既存 3 シナリオの mc 結果（P7 時点）が変わらない（決定論ハッシュ一致）。fixture バンドルで s01 相当のシナリオが最後まで走る。一辺 12,288 m・513 頂点のダミー高さマップで派生レイヤーが 8 秒以内（Worker）に計算できる。`heightmap.test.ts` 合格。

## P14 エディターの骨格とエリア・地形
- `editor.html`、`EditorApp`（タブ・上部バー・自動保存・Undo/Redo）、IndexedDB、プロジェクト一覧（新規・開く・複製・削除）
- `TileMapView`（パン・ズーム・背景切替・出典）、エリア枠、`dem.ts` + `dem.worker.ts`、平滑化、派生レイヤー表示、3D プレビュー
- 新規作成ウィザードの 1〜2 段目

**受け入れ**: 任意の山域（例: 北緯 36.40 東経 137.71 付近、一辺 6 km）を選ぶと、10 秒程度で 3D の箱庭が表示される。プロジェクトを閉じて開き直しても地形が復元される。`projection` / `dem` テスト合格。

## P15 登山道・地点・環境
- `overpass.ts`（取得とグラフ変換、下書き→確定）、`gpx.ts`、手描き編集、エッジ・ノード・危険箇所のインスペクタ、紛らわしい分岐の自動提案と編集表、ID の一括書き換え
- 植生（森林限界の提案、ブラシ塗り）、電波（基地局、塗り）、地図上の検証マーカー

**受け入れ**: 取り込んだ OSM の登山道から計画ルートを引け、標準登山者のヘッドレス試走で下山口に到達する。GPX を取り込んで計画ルートにできる。`overpass` / `gpx` テスト合格。

## P16 天候エディター
- タイムライン（編集・範囲操作・目印）、確認地点と局地値表、9 種の天気パターン（プレビュー→適用）、雷雲セルの地図編集、Open-Meteo 取り込み（換算・間引き・比較表示・出典）、予報の表と自動下書き

**受け入れ**: s01 の天候を「寒冷前線 s=1」から 10 分以内に作り直せる（手順を `docs/PROGRESS.md` に記録）。取り込んだ過去の天気がタイムラインに表示され、局地値が妥当な範囲（山頂気温が基準より低い等）。`openmeteo` / `presets` テスト合格。

## P17 シナリオ編集
- シナリオ情報（日の出入り自動計算）、登山者カードと装備プリセット、計画ルートの地図クリック入力、分岐点一覧と編集、条件ビルダー、アクション編集、イベント・思考・結末・教訓、テンプレート、JSON タブ、検証パネル

**受け入れ**: エディターだけで（JSON を手で書かずに）s02 と同等のシナリオを箱庭岳マップ上に作り、検証エラーなし。条件ビルダーで作った条件と JSON 直接編集が往復で一致。

## P18 試走・書き出し・仕上げ
- 試走（1 回・まとめて、Worker）、結果表示、balanceTargets の合否と提案、3D で遊ぶ連携、書き出し（権利確認ダイアログ、出典の自動付与）、読み込み、シナリオのみ書き出し、マップの共有
- 新規作成ウィザード全体、分岐点テンプレート

**受け入れ**: 実在の山域で、ウィザードから「範囲→登山道→登山者→天候（過去の天気）→分岐点 1 つ→試走→書き出し」まで通せる。書き出したバンドルをプレイヤーで読み込み、3D で最後まで遊べ、出典が表示される。`bundle` テスト合格。

## P19 大人数・グループ・史実シナリオ
- 生理の改訂（年齢、震えの燃料、地面伝導、雨具下の蒸発、浸水、心停止判定）と較正 C10〜C13
- 風による速度・MET・突風転倒（docs/07 §1.1）
- グループ（`groups`、`cohesion`、`splitParty`、`detach`、リーダー交代、`straggler`）、パーティ 20 人
- `initial`、`estimated`、`historical`（方針 `historical`、記録の重ね表示、注記）
- UI: 大人数の登山者パネル（グループごとの折りたたみ一覧、体温順の並べ替え）
- スケルトンマップの結合（docs/16 §8）。`public/scenarios/historical/s04_tomuraushi_2009.json` を実地形で動かす

**受け入れ**:
- C1〜C13 合格（C1〜C9 の再確認を含む）。既存 3 シナリオの balanceTargets を再確認（生理の改訂で外れたら docs/14 §6 の手順で調整）。
- s04 を `historical` 方針で 200 回: 死亡者数の中央値が `deathCountMedian` の範囲。発症（35℃到達）の中央時刻が D0 10:00〜12:00。
- s04 を `recommended` 方針で 200 回: 死亡者 1 人以上の割合 ≤ 5%。
- 振り返りに「実際の記録」が重なって表示される。

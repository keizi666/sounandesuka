# 15 シナリオエディター 概要

実在する日本の山のエリア・登山道・天候の推移を指定して、シナリオを作るブラウザ上のツール。
同じリポジトリの **別エントリ `editor.html`** として作り、シミュレーションのコード（`src/sim`）と描画（`src/view`）を共有する。

## 1. できること

1. **エリアを選ぶ**: 地理院地図の上で範囲（2〜12 km 四方）を指定すると、国土地理院の標高タイルから地形を作り、箱庭にする。
2. **登山道を作る**: OpenStreetMap から登山道・山頂・山小屋・滝を取り込む／GPX（ジオグラフィカ等の軌跡）を取り込む／地図上で手描きする。分岐・廃道・鎖場・紛らわしい分岐を設定する。
3. **環境を整える**: 森林限界・植生の塗り直し、電波の届く範囲（基地局の配置と塗り）、小屋の営業状態。
4. **天候を組み立てる**: タイムラインでキーフレームを編集する。「寒冷前線通過」「夏の雷雨」などの天気パターンを差し込む。過去の実際の日の気象（再解析データ）を取り込んで下書きにする。雷雲の進路を地図上に描く。
5. **シナリオを書く**: 登山者と装備、計画ルート、予報、分岐点（条件をフォームで組み立てる）、イベント、結末、教訓。
6. **試す**: 検証（エラー一覧）、ヘッドレス試走のログ、モンテカルロで結末分布、そのまま 3D で遊ぶ。
7. **書き出す**: マップとシナリオを 1 ファイルにまとめた **バンドル（`*.hakoniwa.json`）** として保存。プレイヤー画面で読み込めるほか、サーバーの `public/scenarios/` に置けば一覧に出る。

## 3. データモデル

### 3.1 プロジェクト（`EditorProject`、IndexedDB に保存）

| 項目 | 内容 |
|---|---|
| `id`, `name`, `createdAt`, `updatedAt` | |
| `map` | `MapDef`（`terrain.type = "heightmap"`）。高さは `heightsBuffer`（ArrayBuffer）に分けて保存し、書き出し時に base64 化 |
| `scenario` | `ScenarioDef` |
| `raw` | 取り込んだ元データ（OSM の JSON、GPX 文字列、Open-Meteo の応答）。再変換用。書き出しには含めない |
| `editorState` | 地図の表示位置、開いているタブ、選択中の要素 |
| `history` | Undo 用スナップショット（最大 50。高さ配列は含めない） |

IndexedDB は `src/editor/store/idb.ts` で扱う（素の API、または確認のうえ小さなラッパーライブラリ）。データベース `hakoniwa-editor`、ストア `projects`（キー `id`）。

### 3.2 バンドル（`HakoniwaBundle`、書き出し形式）

```jsonc
{
  "format": "hakoniwa-bundle",
  "version": 1,
  "createdAt": "2026-11-17T08:00:00+09:00",
  "generator": "hakoniwa-editor 0.1",
  "map": { /* MapDef。terrain.type="heightmap"、data は base64 */ },
  "scenario": { /* ScenarioDef。mapId は map.id */ },
  "attribution": [
    { "id": "gsi", "text": "出典：国土地理院（標高タイル）を加工して作成", "url": "https://maps.gsi.go.jp/development/ichiran.html", "modified": true },
    { "id": "osm", "text": "登山道データ © OpenStreetMap contributors（ODbL）", "url": "https://www.openstreetmap.org/copyright", "modified": true },
    { "id": "open-meteo", "text": "気象の下書き: Open-Meteo（CC BY 4.0）、Copernicus Climate Change Service の情報を使用", "url": "https://open-meteo.com/", "modified": true }
  ]
}
```

- `attribution` は使ったデータ源だけを自動で入れる（手描きだけなら OSM は入らない）。
- 大きさの目安: 257² で約 0.2 MB、513² で約 0.7 MB（gzip 前）。

### 3.3 プレイヤー側の読み込み

- `public/scenarios/index.json` のエントリに `"bundle": "tsubakuro_winter.hakoniwa.json"` を書ける（`file` の代わり）。
- シナリオ選択画面に「ファイルから読み込む」（ドラッグ＆ドロップ可）と「エディターで作ったシナリオ」（同一オリジンの IndexedDB）を追加。
- バンドルの `attribution` はブリーフィング画面と 3D 画面の隅（小さな文字）に必ず表示する。

## 4. ネットワークとデータ源

| 用途 | 提供元 | エンドポイント | 備考 |
|---|---|---|---|
| 背景地図 | 国土地理院 | `https://cyberjapandata.gsi.go.jp/xyz/{std|pale|hillshademap|seamlessphoto}/{z}/{x}/{y}.{png|jpg}` | 出典表示のみで申請不要（リアルタイム読込） |
| 標高 | 国土地理院 | `https://cyberjapandata.gsi.go.jp/xyz/dem_png/{z}/{x}/{y}.png`（z≤14, DEM10B 相当）/ `dem5a_png`（z15, 一部地域） | 無効値は (R,G,B)=(128,0,0) |
| 植生記号（広葉樹林・針葉樹林） | 国土地理院（ベクトルタイル） | `https://cyberjapandata.gsi.go.jp/xyz/optimal_bvmap-v1/{z}/{x}/{y}.pbf`（z16。注記の層 `Anno` の `vt_code` 6321 広葉樹林・6322 針葉樹林） | 出典表示のみで申請不要。取得したタイルは保存して再取得しない（2026-11-19 ユーザーの指定で追加） |
| 登山道・地点 | OpenStreetMap（Overpass API） | `https://overpass-api.de/api/interpreter`（POST） | 1 エリアにつき 1 回の問い合わせ。結果は `raw.osm` に保存し再取得しない |
| 過去の気象 | Open-Meteo Historical | `https://archive-api.open-meteo.com/v1/archive` | 非商用は API キー不要。商用利用ではキーが必要 |

- ネットワークを使うのは **エディターの `src/editor/geo/*` だけ**。`src/sim` は引き続き通信しない。プレイヤーはバンドルさえあればオフラインで動く（背景に地理院地図を貼る任意設定を除く）。
- 取得した生データは `raw` に保存し、同じ範囲の再取得を避ける（相手のサーバーに負担をかけない）。
- 通信失敗時は理由（ネットワーク、429 混雑、範囲外）を表示し、手描き・手入力で続けられるようにする。

## 5. 権利・表示・倫理

1. **出典表示**: 地理院タイルは出典の明示が必要。標高を加工して地形を作るため「加工して作成」と併記する。OSM 由来の登山道を含むバンドルは ODbL の派生データベースになるため、© OpenStreetMap contributors と ODbL を明記する。Open-Meteo は CC BY 4.0。
2. **配布前の確認（人間の作業）**: 標高データを加工したバンドルをサーバーで一般公開する前に、国土地理院コンテンツ利用規約と測量法上の承認の要否を作者が確認する。エディターは書き出し時にこの注意をダイアログで一度表示する（「確認した」チェックで閉じる）。
3. **実在の山であることの表示**: シナリオに `region: { name: "北アルプス 燕岳", real: true }` を持たせ、ブリーフィングと結末に「実在の山を舞台にした架空のシナリオです。登山道・地形データは古い・不正確な場合があり、実際の山行計画には使えません」を表示する。
4. **実在の事故の扱い**: 実在の遭難事故をなぞる場合でも、登場人物は架空にし、実名や個人を特定できる記述は使わない。エディターのシナリオ情報画面にこの方針を注記として表示する。

## 6. 非機能

- 地形の作成（タイル取得込み）: 6 km 四方で 10 秒以内（回線次第。進捗バーを出す）。
- 派生レイヤー（電波の見通し計算含む）は Worker で計算し、513² でも 8 秒以内。
- 自動保存: 変更から 2 秒後に IndexedDB へ。ブラウザを閉じても失われない。
- 地図表示・GPX 解析・JSON 編集などは、手間が減るならライブラリを使ってよい（CLAUDE.md「依存の追加」に従い確認のうえ）。地図ライブラリを使う場合も、背景タイルは本書 §4 の地理院タイルだけにする。

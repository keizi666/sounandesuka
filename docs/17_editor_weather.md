# 17 エディター: 天候（タブ 5）

天候は `ScenarioDef.weather`（`docs/05`）をそのまま編集する。新しい概念は増やさず、編集を楽にする道具を揃える。

## 1. 画面

```
┌ 2D 地図（雷雲の進路・確認地点ピン）─────────────────────┬ インスペクタ ─────────────┐

│   ◎稜線小屋   ◎山頂     ⟶ 雷雲 cb1 の進路               │  時刻 D0 13:30            │
```

## 2. タイムライン（`editor/weather/Timeline.ts`、Canvas2D）

- 変数ごとの行（気温、風速、風向、降水、雲量、雲底高度、視程、雷、気圧、突風）。行は折りたためる。
- キーフレームは **全変数共通の時刻** を持つ（`WeatherKeyframe` の形のまま）。時刻の縦線をドラッグで移動、ダブルクリックで追加（その時刻の補間値で作る）、Delete で削除。
- 各行の点を上下ドラッグで値を変える（Shift で細かく）。風向は矢印をドラッグして回す。
- 複数キーフレームを範囲選択して「値を ±n」「時間をずらす」「強さを ×k（基準値からの差を拡大縮小）」。
- 時刻軸の下に、日の出・日の入り、分岐点の発火見込み時刻（直近の試走結果から）、イベントの目印を表示。
- 雲底の行には、箱庭内の主要ノードの標高を水平線で表示（「雲底が稜線小屋より下がる時間帯」が一目で分かる）。

## 3. 局地値の確認

- 地図上に **確認地点** を最大 4 つ置ける（既定: 最高点、計画ルート上の最高ノード、小屋、登山口）。
- タイムラインのカーソル時刻での局地気象（`sampleLocal`）を表で表示: 気温、体感温度、風速、降水と種別、視程、雲の中か、雷。
- 「この地点の推移をグラフ表示」で、局地値の時系列を基準値に重ねて表示。
- 作者がよく使う確認: 「山頂は何時から氷点下か」「稜線の風は何 m/s になるか」「何時に雲の中に入るか」。

## 4. 天気パターンの挿入（`editor/weather/presets.ts`）

「パターンを挿入」→ 種類・中心時刻 `t0`・強さ `s`（0.5〜1.5）・方向などを選ぶと、既存のキーフレームに **重ねる** 形でキーフレームを生成する。
挿入前にタイムライン上に半透明でプレビュー表示し、「適用」で確定（Undo 可）。生成後は普通のキーフレームとして自由に編集できる。
`scenario.weather.presetLog` に挿入履歴（種類・時刻・強さ）を残す（表示用、シミュレーションには使わない）。

表の値は基準標高 1,000 m の値。`base` は `t0` 時点の既存の補間値。`Δ` は base からの差、`→` は絶対値。

### 4.1 寒冷前線の通過 `coldFront`（引数: 通過時刻 t0, 強さ s）

| 時刻 | 気温 | 風速 | 風向 | 降水 | 雲量 | 雲底 | 視程 |
|---|---|---|---|---|---|---|---|
| t0−3h | Δ0 | ×1.2 | →220 | →0 | →0.7 | Δ−300 | 維持 |
| t0−1h | Δ0 | ×1.5 | →220 | →2s | →1.0 | →基準+900 | →8000 |
| t0 | Δ−1s | →9s | →260 | →8s | 1.0 | →基準+700 | →3000 |
| t0+1h | Δ−3s | →9s | →300 | →6s | 1.0 | →基準+700 | 3000 |
| t0+3h | Δ−5s | →8s | →310 | →3s | 1.0 | →基準+800 | 4000 |
| t0+6h | Δ−6s | →6s | →320 | →1 | 0.8 | →基準+1100 | 8000 |

（`基準` = refElevM。s01 の天候はこのパターン s=1.0 をもとに調整したもの）

### 4.2 温暖前線の接近 `warmFront`（t0 = 降り出しの中心）

t0−12h 雲量 0.5・雲底 +4,000 → t0−6h 雲量 0.8・雲底 +2,000 → t0−2h 霧雨 0.5・雲底 +800・視程 10,000 → t0 降水 3s・雲底 +300・視程 3,000・風 SE（140°）5s → t0+4h 気温 Δ+3s・降水 1・雲底 +600。

### 4.3 南岸低気圧（雪）`southCoastLow`（t0 = 最盛期、冬向け）

t0−9h 雲量 0.9、風 NE（45°）3 → t0−3h 降水 2s → t0 降水 4s・風 NE 7s・気温 →0（基準）・雲底 →基準 → t0+6h 降水 1・風 NW 6 → t0+9h 晴れ間（雲量 0.5）・風 NW 8・気温 Δ−3。

### 4.4 冬型の季節風 `winterMonsoon`（引数 side: `sea`（日本海側）/ `pacific`（太平洋側））

| 時刻 | sea | pacific |
|---|---|---|
| t0 | 風 NW（310°）→ 10s、気温 Δ−5、降水 →1.5s（雪）、雲量 1.0、雲底 →基準+300、視程 2,000 | 風 NW → 10s、気温 Δ−5、降水 0、雲量 0.3、視程 30,000 |
| t0+6h | 風 →14s、降水 →2.5s | 風 →14s |
| t0+18h | 風 →10s、降水 →1 | 風 →10s |
| t0+30h | 風 →6、降水 →0.3、雲量 0.7 | 風 →6 |

### 4.5 夏の雷雨（熱雷）`summerThunderstorm`（t0 = 雷雲のピーク時刻）

- キーフレーム: t0−4h 雲量 0.4（積雲）、t0−2h 雲量 0.6・雷 0.1、t0 雲量 0.95・雲底 →基準+1,100・降水 2・雷 0.3・突風 0.5、t0+2h 雲量 0.7・雷 0.1・降水 0.5、t0+4h 雲量 0.4・雷 0。
- 加えて `thunderCells` に 1 つ追加: `from = t0−70分`, `peakAt = t0`, `to = t0+80分`, `radiusM = 1,400 × s`, `peak = min(1, s)`, `heavyRainMmH = 25s`, `hail = s ≥ 1`。進路は「地図上で 2 点をクリック」（既定: エリアを南東→北西に横切る直線）。

### 4.6 霧（層雲・ガス）`fog`（引数: 雲底 m, 持続時間 d）

t0−1h 雲量 →0.9・雲底 →指定+300 → t0 雲量 1.0・雲底 →指定・霧中視程 40・霧雨 0.3 → t0+d 維持 → t0+d+2h 雲底 →指定+800・雲量 0.7。

### 4.7 梅雨前線の長雨 `baiuRain`

t0 から d 時間、降水 2s〜8s を 3 時間周期で上下（sin）、雲底 →基準+500、気温は変えない、風 SW 4。

### 4.8 台風の接近 `typhoon`（t0 = 最接近）

t0−24h 風 →6・雲量 0.8 → t0−12h 風 →10s・降水 3s → t0−3h 風 →18s・降水 15s・視程 1,500 → t0 風 →22s・降水 25s・風向は進路で東側通過なら SE→S→SW、西側通過なら E→NE→N（引数 side）→ t0+6h 風 →12・降水 3 → t0+12h 吹き返し 風 →10・降水 0。

### 4.9 移動性高気圧（晴天と放射冷却）`highPressure`

t0 から 24h: 雲量 →0.1、風 →2、降水 0、視程 40,000。夜間（日没〜日の出）は気温を Δ−6s まで下げ、日中は Δ+2 に戻す（キーフレームを日没・日の出・正午に打つ）。

> これらは教材用の **型** であり、実際の気象を正確に表すものではない。作者が局地値を確認して調整する前提。

## 5. 過去の天気を取り込む（`geo/openmeteo.ts`）

「実際にあったあの日の天気で」シナリオを作るための **下書き** 機能。

### 5.1 問い合わせ

```
GET https://archive-api.open-meteo.com/v1/archive
  ?latitude={centerLat}&longitude={centerLon}
  &start_date={YYYY-MM-DD}&end_date={YYYY-MM-DD}
  &hourly=temperature_2m,dew_point_2m,precipitation,snowfall,cloud_cover,cloud_cover_low,wind_speed_100m,wind_direction_100m,wind_gusts_10m,pressure_msl
  &wind_speed_unit=ms&timezone=Asia%2FTokyo
```

- 期間はシナリオの開始日〜終了日（最大 3 日）。データは数日遅れで更新されるため、直近数日は取れない場合がある（UI に表示）。
- 応答の `elevation`（格子の標高）を記録。無い場合は作者に入力を求める。
- 応答そのものを `raw.weather` に保存。

### 5.2 変換（1 時間ごとのキーフレームを作る）

| シナリオの値 | 変換 |
|---|---|
| `tempC`（基準標高） | `temperature_2m + lapse × (elevation − refElevM) / 100` |
| `windMs`, `windDirDeg` | 100 m 風を使用 × 作者の補正倍率（既定 1.0）。地形による強まりは局地モデルが加えるので、ここでは強めない |
| `gustiness` | `clamp((gusts_10m / max(1, wind_10m 相当) − 1) / 2, 0.1, 0.6)`。wind_10m は取得しないので 100 m 風 × 0.75 で近似 |
| `precipMmH` | `precipitation × 山岳補正`（既定 1.3。再解析は格子が粗く山の降水を弱めに出すため） |
| `cloudCover` | `cloud_cover / 100` |
| `cloudBaseM` | `cloud_cover_low ≥ 50` のとき持ち上げ凝結高度の近似 `elevation + 125 × (T − Td)`、それ以外は `max(上記, 3,500)` |
| `visibilityM` | 視程は取れないので推定: 雲の外 20,000、降水があれば `docs/05` §2.4 の式に任せる。湿度が高い（T − Td < 1）ときは 5,000 |
| `thunder` | 0（再解析では雷を再現できない。必要なら作者が雷雲セルを置く） |
| `pressureHpa` | `pressure_msl` |

- 変換後に **間引き**: 各変数で前後のキーフレームから線形補間した値との差が閾値（気温 0.5℃、風 1 m/s、降水 0.5 mm/h、雲底 100 m）未満のキーフレームを、全変数で満たす場合のみ削除。
- 取り込み画面で、原データ（点）と変換後（線）を並べて表示し、補正倍率を変えて結果を確かめられるようにする。
- 取り込んだシナリオの情報に「気象の下書き: Open-Meteo（ERA5 再解析）、{日付}、{緯度経度}」を自動で記録し、attribution に Open-Meteo を加える。
- 注意書き（UI）: 「再解析データは数十 km 規模の平均で、山の局地的な天気（稜線の強風、谷の霧、雷雨）は再現されません。下書きとして使い、局地値を確認して調整してください。」

## 6. 雷雲セルの編集

- 地図上で進路の始点・終点（中間点も可）をクリック。半径を円で表示し、ドラッグで変更。
- タイムラインの「雷」行に、各セルの時間包絡（from–peakAt–to）を帯で表示し、ドラッグで時刻を動かす。
- 選択中のセルについて、「この進路だと各ノードで雷の強さが最大になる時刻と値」を表で出す。

## 7. 予報（登山者が見た予報）

- `briefing.forecast` を表で編集（ラベル、文、アイコン）。
- 「タイムラインから下書き」ボタン: 朝・昼・夕方・夜の代表値から文を自動生成（例: 降水 > 1 → 「雨」、雲量 > 0.7 → 「くもり」、雷 > 0.1 → 「所により雷雨」、風 > 10 → 注意報「強風」）。そのあとで、**わざと楽観的に書き換える**（実際より遅い雨の予報など）ことを想定し、作者が編集する。
- イベントの `forecastUpdate`（途中で届く予報の更新）も同じ表で編集できる。

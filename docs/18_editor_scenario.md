# 18 エディター: シナリオ編集・試走・書き出し（タブ 6〜9, JSON）

形式はすべて `docs/09_scenario_format.md` のとおり。エディターはそれをフォームで編集する道具であり、独自の保存形式を持たない。

## 1. シナリオ情報（タブ 6 の上部）

題名、副題、テーマ、難易度、季節、所要時間の目安、乱数シード、開始日、開始時刻、制限時刻、日の出・日の入り（開始日と中心の緯度経度から **自動計算**。NOAA の簡易式で ±2 分。手で上書き可）、月齢（任意）、地域表示 `region`（名前、実在かどうか）。

日の出入りの自動計算は `src/sim/core/clock.ts` ではなく `src/editor/geo/sunrise.ts` に置く（sim はシナリオの値を使うだけ）。

## 2. 登山者と計画（タブ 6）

### 2.1 登山者

- 1〜3 人のカード。各項目は `docs/09` §3 のとおり。
- 数値はスライダー＋説明の言葉（経験 0.2「数回」、0.5「数年・日帰り中心」、0.8「積雪期も行く」など）。
- **装備プリセット**: 「日帰り軽装」「日帰り標準」「日帰り万全（ツェルト・予備電池・GPS 記録）」「小屋泊」「冬山」。選んでから個別に変える。
- 色は自動で見分けやすいものを割り当て。

### 2.2 計画ルート

- 地図上でノードを順にクリックして並べる（隣接していないノードをクリックすると最短経路で間を自動補完）。
- 下山口（`goalNodes`）を指定。予定下山時刻を「標準登山者の試算＋休憩」から提案。
- 計画書の提出、家族の通報時刻。
- ルートの区間ごとの予定時刻表（コースタイムと試算の両方）を表示。

## 2.5 物語のタブ（タブ 6。分岐点と結末のタブをまとめた）

ユーザーの指摘（エディターが複雑すぎる。テンプレートを充実させ、イベント・分岐・結果を直感的に操作したい）を受け、もとの「分岐点」「結末」の
2 つのタブを **「物語」** の 1 つにまとめた。左のタブは「山を作る（エリア・登山道と地点・環境）→ 物語を作る（天候・人と計画・物語）→ 試す（試走）→ 上級（JSON・AI）」の見出しで分ける。

- **ボード**（中央。地図の上に重ねる。`panels/storyBoard.ts`）: 分かれ道（分岐点）・できごと（イベント）・会話と心の声・結末・教訓をカードで並べる。
  - 「道のりにそって起きること」: 計画ルートの名前のある地点を縦に並べ、その地点に着いたときに起きるカードを下に置く。地点の「＋ ここで起こす」でその地点のテンプレートを開く。
  - 「時刻で起きること」「条件がそろったら起きること」（自動で出る汎用の分岐点のカードを含む）、「会話・心の声」、「結末」（8 種類の終わり方ごと。書いていなければ既定の文を薄く出す）、「教訓」。
  - 分かれ道のカードは、選択肢ごとに「★／⚠ ラベル → 選ぶとする行動」を出し、その選択を条件にしている結末・教訓・できごとをつながりとして出す。試走のあとは、出た時刻と選んだ選択肢も出す。
  - 文の中の `{leader.local.tempC:0}` などは、カードでは〔気温〕のような言葉で見せる。
- **右の欄**（`panels/storyInspector.ts`）: 選んだカードをやさしい言葉の欄で直す。「いつ」は `forms/whenPicker.ts` の選ぶ欄
  （地点に着いたとき・時刻になったら・雨が降り始めたとき・予定より遅れたら…、結末と教訓は「雨具を着るのが遅れた」「分かれ道でこれを選んだ」…）。
  「起きる確率」は `{ all: [条件, { chance }] }`。選ぶ欄で表せない条件は言葉の要約を出す。
  ID・条件ビルダー・利用条件・自律バイアス・制限時間などは「くわしい設定」に畳む（§3・§4 の欄。`panels/choiceDetail.ts`・`panels/storyDetail.ts`）。
- **テンプレートの一覧**（`panels/templateGallery.ts`、中身は `templates/story*.ts`）: 「物語の型」（部品のまとめ: 天気が崩れる日帰り・遅れと日暮れ・疲れた仲間・けがと救助・動物との遭遇）、
  分かれ道 12、できごと 10、会話・心の声 7、結末・教訓 6。計画ルートの地点・小屋・開始時刻に合わせて作り、ID が重なれば番号を付ける。物語が空のときは、ボードの上に物語の型を並べる。
- 条件の要約（`summarize`）は、出来事を「雨が降り始めた」のような言葉で、比較を「〜が 35 より小さい」のように出す。

## 3. 分岐点（物語のタブの「くわしい設定」）

### 3.1 一覧

表形式: ID、題、発火条件の要約、選択肢数、`recommended` の有無、直近の試走での発火回数（「一度も発火していない」分岐点を警告）。

### 3.2 分岐点の編集

- 題、状況の文、「登山者が把握していること」、制限時間、優先度。
- 文の入力欄では `{` を打つと変数パスの候補を出す（`leader.local.windChillC` など。`docs/09` §4.1 の一覧から生成）。右側に、直近の試走のその時点の値で展開したプレビューを表示。
- **選択肢**: ラベル、補足、タグ（推奨・危険）、利用条件、アクション列、立てるフラグ、自律バイアス。
- アクションはドロップダウンで種類を選び、種類に応じた入力欄（ノード選択は地図クリックでも可）。

### 3.3 条件ビルダー（`editor/forms/ConditionBuilder.ts`）

条件 DSL をツリーで組み立てる UI。

```
[すべて満たす ▼]
 ├ [リーダーの深部体温 ▼] [< ▼] [35.3]           ✕
 ├ [状態ではない ▼] [ビバーク ▼]                   ✕
 └ [いずれか ▼]                                     ✕
     ├ [時刻以降 ▼] [D0 ▼][14:00]                   ✕
     └ [ノードに到着 ▼] [稜線小屋 ▼]（地図で選択）  ✕
 [+ 条件] [+ グループ]
```

- 条件の種類は `docs/09` §4 の表と 1 対 1。変数比較の左辺はカテゴリ別の選択肢（登山者 / 局地気象 / 全体気象 / 時刻 / 記録 / フラグ）。
- 右上に「JSON を見る」トグル（その条件の JSON をその場で編集可）。
- 「今の試走でこの条件が初めて真になった時刻」を表示（直近の試走レコードを使って評価）。

## 4. イベント・思考・結末・教訓（物語のタブ）

- スクリプトイベント: 発火条件（条件ビルダー）＋効果のリスト（`docs/09` §8 の種類から選ぶ）。
- 思考テンプレート: キー、条件、文のリスト、優先度。
- 結末: 種類ごとに、条件つきの題と文を並べる（上から評価されることを UI で示す）。
- 教訓: 条件、題、文（`{rec.*}` の候補補完つき）。

## 5. 検証パネル（常時）

- 上部バーに「⚠ 警告数 ✖ エラー数」。クリックで一覧。各項目をクリックすると該当タブ・該当フィールドへ移動し、地図上の位置があればそこにパンする。
- 検証は `src/sim/scenario/validate.ts` をそのまま使い、エディター固有の警告（未確定の道、出典の欠落など）を追加する。
- エラーがある間は「試走」「3D で遊ぶ」「書き出し」を無効にする。

## 6. 試走（タブ 9）

### 6.1 1 回の試走

- 方針（推奨 / その人らしく / ランダム / 危険）とシードを選んで実行。Worker でヘッドレス実行。
- 結果: 結末、時系列グラフ（`docs/12` の DebriefScreen のグラフ部品を再利用）、地図上の軌跡（色＝体温）、イベントログ、各分岐点の発火時刻と選んだ選択肢。
- ログの行をクリック → その時刻にタイムラインのカーソルを合わせ、地図で位置を示す。

### 6.2 まとめて試す（モンテカルロ）

- 方針ごとに N 回（既定 200）。Worker 2 本で並列。
- 結末の分布（棒グラフ）、最低体温の分布、分岐点ごとの選択の割合、道迷いの発生率、死亡原因の内訳。
- `balanceTargets` の入力欄と合否表示。「現在の分布から目標を提案」ボタン（推奨方針の good 率 −5% などを初期値にする）。

### 6.3 3D で遊ぶ

現在のプロジェクトをバンドル化して、プレイヤー画面（`index.html`）を新しいタブで開く（`BroadcastChannel` または IndexedDB 経由で受け渡し。URL パラメータ `?bundle=editor:<projectId>`）。

## 7. JSON（`{ }` タブ）

- マップとシナリオの JSON をテキストで編集（`<textarea>`、等幅、行番号は自作の簡易表示）。
- 「適用」で解析・検証し、成功すればプロジェクトに反映（Undo 可）。失敗時はエラー位置を表示し、反映しない。
- 高さデータ（base64）は表示しない（`"data": "<省略: 513×513>"` と表示し、保存時に元のデータを保持）。

## 8. 書き出し・読み込み

| 操作 | 内容 |
|---|---|
| 書き出し | `*.sounan.json`（バンドル）をダウンロード。初回は権利確認ダイアログ（`docs/15` §5.2） |
| シナリオのみ書き出し | 既存マップ（例: 箱庭岳）を使うシナリオのとき、シナリオ JSON だけを書き出す |
| 読み込み | バンドル、シナリオ JSON（既存マップ参照）、旧版のマップ JSON を読み込んでプロジェクト化 |
| 複製 | プロジェクトを複製（同じ山で別の天候のシナリオを作る用途） |
| マップの共有 | 「このプロジェクトのマップを使って新しいシナリオ」— マップ部分をコピーした新プロジェクトを作る |

## 9. 新規作成の流れ（ウィザード）

初回は次の順に誘導する（後からいつでも各タブで直せる）:

1. 「架空の箱庭岳で作る」か「実在の山で作る」かを選ぶ。
2. （実在）地図で範囲を置く → 標高を取得 → 3D で確認。
3. （実在）OSM の登山道を取り込む → 使う道を確定。
4. 登山者を 1 人作り、計画ルートをクリックで引く。
5. 天候: 「晴れのまま」「パターンから」「過去の天気から」を選ぶ。
6. 推奨方針で 1 回試走して、結末まで走ることを確認。
7. 分岐点を 1 つ作るよう促す（テンプレート: 「引き返し判断」「雨具」「小屋で泊まるか」「道迷いに気づいた」）。

### 分岐点テンプレート

| テンプレート | 生成内容 |
|---|---|
| 引き返し判断 | 指定ノード到着で発火。選択肢: 進む(risky) / 引き返す(recommended) / 近くの小屋へ |
| 雨具 | `RAIN_START` かつ未着用で発火。すぐ着る(recommended) / 着いてから(risky) |
| 小屋で泊まるか | 小屋ノード到着で発火。泊まる(recommended) / 先へ(risky) / 引き返す |
| 道迷いに気づいた | 汎用 `lostAware` の文を上書き（既定の選択肢を使う） |
| 雷 | 汎用 `lightning` の文を上書き |

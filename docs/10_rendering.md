# 10 3D 描画（`src/view/`）

three.js（WebGL2）。`view` は `World` を **読むだけ**。描画用キャッシュは `view` 内に持つ。

## 1. スケールと単位

- three のシーン単位 = **1 m / 1000**（箱庭岳は 4.1 単位、実在エリアは最大 12.3 単位）。カメラの距離制限・影カメラ・雲や降水の配置範囲はすべて `map.def.size` に比例させる。
- 鉛直誇張 `vExag`（設定、既定 1.0）。`y = (elevM - baseElevation + plinth) / 1000 * vExag`。
- 登山者フィギュアの拡大率 `figureScale`（設定、既定 25 倍。等身大だと 1.7 mm で見えない）。

## 2. シーン構成

```
Scene
├─ DioramaRoot
│  ├─ Plinth          木の台座（BoxGeometry、角に面取り）＋真鍮プレート（CanvasTexture: 山名・日時）
│  ├─ TerrainMesh     高さマップ（品質で解像度切替）
│  ├─ SideWalls       4 面の断面（地層の縞は y からシェーダで生成）
│  ├─ Water           沢のリボン（stream セルを細線化したポリライン、幅 3〜8 m）
│  ├─ Vegetation      InstancedMesh: 広葉樹 / 針葉樹 / ハイマツ / 低木（§5.2。近景は枝葉つき、遠景は板ポリゴン）
│  ├─ Trails          登山道リボン（地表 +0.5 m、破線テクスチャ）。偽の道は神の視点で薄く表示
│  ├─ Structures      小屋・避難小屋・山頂標識・道標（§5.3）
│  ├─ Climbers        人形（§5.1）＋選択リング＋ヘッドランプの SpotLight（夜のみ、最大 3）
│  ├─ TrackLines      実際の軌跡（Line2 ではなく細いリボンで太さを確保）
│  ├─ Overlays        気温・風・電波などの面（地形に重ねる半透明メッシュ）
│  ├─ Pins            注目ピン（ビルボード）
│  └─ WeatherFX
│     ├─ CloudLayer   雲底に置く雲（インスタンス化したソフトパーティクル）
│     ├─ Cumulonimbus 雷雲セル（縦に積んだパーティクル塊）
│     ├─ Precip       雨・雪・ひょうの GPU パーティクル（箱の内側にのみ）
│     └─ Lightning    稲妻（ジグザグのライン）＋フラッシュ
├─ Sky                グラデーションの天球（太陽高度・雲量で色変化）＋星（夜）
├─ SunLight           DirectionalLight（影あり、shadow camera は箱庭に合わせる）
├─ Hemisphere         空と地面の環境光
└─ Table              箱庭が置かれた机（大きな平面、ぼかしたテクスチャ）
```

## 3. 地形

### 3.1 メッシュ

| 品質 | 頂点 | 影 | 樹木インスタンス | 雲パーティクル | 降水粒子 |
|---|---|---|---|---|---|
| 低 | 129² | なし | 4,000 | 150 | 4,000 |
| 中 | 257² | 1024 | 12,000 | 300 | 10,000 |
| 高 | 257² + 法線マップ | 2048 | 25,000 | 600 | 20,000 |

`BufferGeometry` を自作し、頂点属性に `veg`（float）、`tpi`、`slope` を持たせる。

### 3.2 マテリアル（`terrainMaterial.ts`）

`MeshStandardMaterial` を `onBeforeCompile` で拡張:

- **色**: 頂点の植生クラスで基本色（広葉樹 #5b7f3a、針葉樹 #3e5f37、ハイマツ #55703f、草地岩礫 #8c8a73、岩 #7b7670、沢 #6c7e86、崖 #5d5751）。斜面方位で微妙に明度変化。`flatShading` は使わない。色の量子化はせず、近距離ではディテール用のノイズテクスチャ（Canvas で生成）で岩・草・土の質感を出す（精密なジオラマ模型の見た目。写真レベルは目指さない）。
- **積雪**: uniform `snowLineM`（ground の `snowCm` が 1cm 以上の最低標高）と `snowCmAtTop`。`elev > snowLine` かつ `slope < 50°` で白を混ぜる。
- **濡れ**: `wet` が高い標高帯は彩度・明度を 15% 下げ、スペキュラを上げる。
- **高度フォグ**: uniform `cloudBaseM`, `cloudCover`。フラグメントの標高が雲底より上なら、カメラとの距離に応じて灰白色を混ぜる（`fogAmt = smoothstep(cloudBase-80, cloudBase+60, elev) * cloudCover * 0.85`）。俯瞰でも「稜線が雲に隠れている」状態が一目でわかる。
- **夜**: 太陽光の強度を下げ、`nightTint`（青）を乗算。ヘッドランプ SpotLight のみが局所的に照らす。

同じフォグ処理を樹木・構造物のマテリアルにも共有関数として注入する。

### 3.3 側面の断面（`SideWalls`）

地形の外周の頂点列から台座上面まで垂直な面を作り、`y` に応じた縞（表土・礫層・岩盤）をシェーダで描く。上端は植生色を少し残す。

## 4. 気象表現

| 現象 | 実装 |
|---|---|
| 雲層 | 雲底 `cloudBaseM` の高さにソフトパーティクル（ノイズテクスチャのビルボード）をグリッド状に配置。`cloudCover` で表示数、風向で流す。厚み = `cloudTop - cloudBase`（既定 600 m）に 2〜3 層 |
| 霧（雲中） | 地形マテリアルの高度フォグ（§3.2）。雲中の登山者フィギュアもフォグで霞む |
| 雨 | `LineSegments` の粒子。箱庭の範囲内で上から落とし、風で傾ける。強度 = `precipMmH` を 0〜20 mm/h で 0〜最大粒子数に写像。雲底より上の発生源から |
| 雪・みぞれ | `Points`（丸テクスチャ）。ゆっくり揺れながら落下。種別は標高で判定し、シェーダで粒子の高さに応じて雨⇄雪を切替（雪線より上は雪） |
| ひょう | 白い小さめの粒、落下速度大 |
| 雷雲 | セル中心に積乱雲（下部が暗い縦長の塊）。`thunder` 強度で不透明度 |
| 稲妻 | `thunderLocal` に比例した頻度でセル内のランダム地点に 0.15 秒表示（`thoughts` 以外の描画用乱数＝ `view` 内の Math.random 可）。同時に環境光をフラッシュ |
| 風 | オーバーレイ ON のとき矢印（InstancedMesh）を 16×16 で表示。長さ = 局地風速 |
| 時刻 | 太陽方向・色温度（朝夕は橙、昼は白、夜は月光）。天球の色をグラデーションで補間 |

## 5. モデル

目標は **精密なジオラマ模型**。写真レベルの写実は目指さない。地形・樹木・建物は模型として写実寄りに作り、人はブロック玩具風の人形にする（博物館のジオラマに玩具の人形を置いた見た目）。
形とテクスチャはコードで手続き生成する（基本部分は画像ファイルを持たない）。

### 5.1 登山者の人形（`climberFigure.ts`）

- 様式: ブロック玩具風の人形。レゴのミニフィギュアを参考にするが、特定製品の形をそのまま写さずオリジナルの形にし、商標・ロゴは使わない。
- 部品: 頭（円柱。顔は Canvas テクスチャ）、胴（上が狭い台形）、腕 左右（肩で回る）、手 左右、腰、脚 左右（股関節で前後に回る）。各部品は剛体で、関節の回転だけで姿勢を作る（スキニングなし）。
- 材質: 樹脂のつや（`MeshPhysicalMaterial` の clearcoat）。
- 付け替え部品（装備に合わせる）: 帽子 / ヘルメット / 雨具のフード、ザック（`packKg` で大きさ 3 段階）、ヘッドランプ（額の小さな光る部品）、トレッキングポール、ツェルト使用時は小さなオレンジのテント形状。
- 雨具: 着用中は胴と腕を `ClimberDef.color` のつやの強い材質に替え、フードを付ける。未着用時は服の色（登山者 ID から決める落ち着いた色）。
- 濡れ: `wetness` に応じてつやを上げ（roughness を下げる）、色を少し暗くする。
- 顔の表情（テクスチャの切替）: 通常 / 疲れ（fatigue > 75）/ 寒い（core < 35.5、口を結ぶ）/ 目を閉じる（意識なし・死亡）。苦痛や恐怖を強調する表情は作らない。
- 姿勢（関節角を時間で動かす。姿勢の切替は 0.4 秒で補間）:

| 状態 | 姿勢 |
|---|---|
| 移動中（WALKING ほか） | 脚と腕を交互に振る。周期は移動速度に連動 |
| RESTING / BIVOUAC / WAITING_RESCUE / STAYING | 座る（股関節 90°）。STAYING で強風のときは立ったまま背を丸める |
| 雷しゃがみ・突風の耐風姿勢 | しゃがむ |
| 震え（core < 36.0 で停止中） | 体全体を小刻みに揺らす（振幅は段階で変える） |
| 軽度低体温症で歩行中 | 歩幅を不規則にし、左右に少しふらつく |
| INCAPACITATED / UNCONSCIOUS | 横向きに倒れる |
| DEAD | 横向きに倒れたまま静止し、人形とマーカーが静かに灰色になる |

- 補間: `prevPos` → `currPos` を `alpha` で線形補間。向きは移動方向に slerp。
- 足元に選択リング（選択中は脈動）。夜はヘッドランプ（SpotLight + 小さな光球）。電池切れで消灯。
- 大きさ: `figureScale`（既定 25 倍）で拡大する。玩具の人形として見えるので拡大しても不自然にならない。登山者視点カメラでは実寸。
- 三角形数: 近景 約 1,500〜3,000。画面上の高さ 12px 未満では部品を統合した簡略形（約 200）に切り替える。
- 情報モード「登山者の視点」では、道迷い中の人形は `routeBelief` 位置に半透明で表示し、真の位置は描かない。

### 5.2 樹木（`vegetation.ts`）

- 種類: 広葉樹（ブナ・ミズナラ風）、針葉樹（オオシラビソ風）、ハイマツ、低木。植生クラスで配置し、大きさ・傾き・色に個体差を付ける。
- 近景: 幹と主な枝のメッシュ＋葉の板（Canvas で生成した葉群のテクスチャ、アルファ切り抜き）。遠景: 起動時に描いておく板ポリゴン（インポスター）。距離で切り替える。
- 風: 頂点シェーダで局地風に応じて揺らす（幹は小さく、梢と葉は大きく）。
- 季節: シナリオの `season` と日付で葉の色を変える（秋は広葉樹が紅葉、冬は落葉して枝だけ）。
- 積雪: 標高帯の `snowCm` に応じて枝・葉の上面を白くする。

### 5.3 建物・人工物（`structures.ts`）

- 営業小屋: 石積みの土台、板張りの壁、トタン屋根、煙突、窓（夜は灯りが点く）。避難小屋: 小さく、石積みまたはかまぼこ型。
- 山頂標識・道標: 木の柱と板（文字は読めなくてよい）。
- 鎖場は岩に沿った細い鎖。
- 質感は Canvas で生成したテクスチャ（木目・石・トタンの波板）。

### 5.4 ほかの登山者の列（`crowds.ts`）

- シナリオの `crowds`（docs/09 §1）。夏の富士山のご来光の列など（ユーザーの指定）。位置は補間した時刻と、人の番号のハッシュだけで決める（sim の状態・乱数に触れない。一時停止すれば止まる）。
- 人形は胴（上着の色はハッシュで選ぶ）・頭・帽子・脚・ザックの簡単な形を InstancedMesh で描く（最大 600 人）。主役の人形の 0.4 倍の大きさで、影を落とさない。道の中心から少し左右にずらし、歩く上下の揺れを付ける。
- 暗い（`uNight` > 0.35）あいだは、額の前にヘッドランプの光の点（加算合成の Points）を付け、光の列にする。

## 6. カメラ（`camera.ts`）

| モード | 操作 |
|---|---|
| 俯瞰 | OrbitControls（`three/examples/jsm/controls/OrbitControls.js`）。極角 15°〜80°、距離 2〜12 単位、ターゲットは箱庭内に制限 |
| 追従 | 選択中の登山者を中心にスムーズ追従（減衰 0.08）。回転は可能、パン不可 |
| 登山者視点 | 目の高さ（地表 +1.6 m の実寸）から進行方向を見る。`scene.fog` を局地視程に合わせた `FogExp2`（`density = 3.0 / vis`）。夜はヘッドランプの範囲以外ほぼ黒。ここだけ `figureScale` を無視し実寸 |

モード切替は 0.6 秒のトゥイーン。

## 7. オーバーレイ（`overlays.ts`）

地形メッシュと同じジオメトリを共有し、別マテリアルで `polygonOffset` して重ねる（64×64 のデータテクスチャを 1 ゲーム分ごとに更新）。

| 種類 | 色 |
|---|---|
| 気温 | 青（−10℃）→ 白（5℃）→ 橙（20℃） |
| 体感温度 | 同上 |
| 風 | 白→紫（0〜25 m/s）＋矢印 |
| 電波 | 緑（強）→ 黄 → 透明（圏外） |
| 雲中 | 雲底より上を灰色ハッチ |
| 危険 | 崖・滝・鎖場を赤の縁取り |

## 8. 実在エリアの表示

- 地形メッシュの頂点数は sim の `resolution` に合わせる（低品質では 1/2 に間引く）。513² は高品質のみ全頂点、中品質は 385² 相当に間引く。
- 地形の色は既定で植生クラスの塗り分け（オフラインで動く）。設定「地形の色: 植生 / 地理院地図 / 空中写真」を追加し、`map.def.geo` があり通信できる場合のみ、地理院タイル（`std` / `seamlessphoto`、z14〜15）を 1 枚の大きな Canvas に貼り合わせてテクスチャにする。読み込みに失敗したら植生色に戻す。出典は画面隅に表示。
- 台座の真鍮プレートにはエリア名（`map.def.name`）と「実在の山を舞台にした架空のシナリオ」を表示。

## 9. 性能指針

- ドローコール 150 以下（中品質）。樹木は種別×詳細度ごとに 1 InstancedMesh。
- 人形・樹木・建物は距離で詳細度を切り替える（LOD）。低品質では近景モデルを使わず、簡略形と板ポリゴンだけを使う。
- 毎フレームの確保（`new Vector3` 等）を避け、モジュールスコープの作業用オブジェクトを再利用。
- 降水粒子の更新は頂点シェーダ内で時間から位置を計算（CPU 更新しない）。
- 影の更新は太陽が 0.5° 動いたときのみ（`shadowMap.autoUpdate = false`）。
- `renderer.setPixelRatio(min(devicePixelRatio, 品質で 1〜2))`。
- 可視性: タブ非表示時はループを止める（`visibilitychange`）。

## 10. アセットの読み込み（`assets.ts`）

- **基本**（初回ロードに含む。NFR-03 の 1.5MB の内）: 手続き生成のコードと、低・中品質で使うモデル・テクスチャ。手続き生成なので画像ファイルは基本的に持たない。
- **追加**（後から読み込む）: 高品質用の高解像度テクスチャやモデル（`public/assets/hq/`）。高品質のとき、シナリオ開始後に裏で読み込み、届くまでは基本のモデルで表示し、届いたら差し替える。失敗したら基本のまま続ける（エラーにしない）。
- 追加分の合計は 20MB 以下を目安にする（スマホのメモリを考え、低・中品質では読み込まない）。
- 外部 CDN は使わず、すべて同じサーバーから読む（NFR-09）。一度も読み込んでいないオフライン時は基本のモデルで動く。
